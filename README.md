# 网络请求监视器（Edge 插件）

不用打开 F12，在一个独立的窗口里查看网页的全部网络请求和响应，界面和用法与 DevTools 的「网络」面板基本一致。网页里打开的新标签页、新窗口会自动跟进去，所有请求汇总在同一个面板里。

## 安装（Edge）

1. 地址栏打开 `edge://extensions`
2. 打开左侧的「开发人员模式」
3. 点「加载解压缩的扩展」，选择本文件夹（包含 `manifest.json` 的那一层）
4. 建议点工具栏的拼图图标，把「网络请求监视器」固定到工具栏

修改代码或更新文件后，在 `edge://extensions` 里点插件卡片上的「重新加载」即可生效。

## 使用

1. 打开要分析的网页
2. 点击工具栏上的插件图标，会弹出一个独立的「网络」窗口，并自动开始记录这个标签页
3. **插件连接之前页面已发出的请求不会被记录**。想看页面加载过程的请求，点窗口里的「重新加载页面」
4. 浏览器顶部会出现「网络请求监视器 已开始调试此浏览器」的提示条，这是浏览器强制显示的。**不要点提示条上的「取消」**，点了监视就会停止，需要在窗口里点「全部重新连接」

## 多个标签页 / 新窗口

一个面板可以同时监视一组标签页，请求全部汇总在一起：

- **自动跟随**：被监视的页面里点链接打开的新标签页、`window.open` 弹出的新窗口，会自动加入监视。新页面里再打开的页面也会继续跟进去，跳到别的网站也一样
- **同网站自动加入**：你自己新开标签页，只要访问的是同一个网站（按主域名判断，例如 `a.example.com` 和 `b.example.com` 算同一个网站），也会自动加入
- **区分来源**：同时监视多个标签页时，列表会多出「标签页」一列（`#1`、`#2`……）。筛选栏可以选「只看某个标签页」，右键菜单里也有「只看此标签页」
- **管理**：点右上角「监视 N 个标签页」，可以看到每个标签页的状态和请求数，可以切换过去、刷新、移除，或手动添加其他标签页，也可以关闭上面两种自动加入

关于新窗口刚打开的那一瞬间：页面本身（HTML）和最早的几个资源请求，往往在插件连上新窗口之前就已经发出了。插件会用浏览器的 webRequest 接口把这些请求**补录**进列表，名称后面标着「·补录」。补录的请求有网址、标头和状态码，但**没有响应内容**。页面后续发出的接口请求都能完整抓到，包括响应内容。

如果连这些最早请求的响应内容也需要，在右上角勾选「自动加入后刷新一次」，新窗口加入时会自动刷新一次。注意：如果新窗口是提交表单打开的，刷新可能会重复提交。

## 功能

| 区域 | 说明 |
|---|---|
| 工具栏 | 记录/暂停（Ctrl+E）、清除、保留日志、禁用缓存、重新加载页面、导出 HAR |
| 保留日志 | 默认开启。关闭后，某个标签页跳转时只清空该标签页自己的记录，其他标签页不受影响 |
| 筛选 | 关键词、正则、排除，以及 `domain:` `method:` `status-code:` `mime-type:` `larger-than:` 等条件（点输入框里的 `?` 查看说明） |
| 搜索内容 | 勾选后，关键词还会在请求体、响应内容、WebSocket 消息中搜索，适合按数据反查是哪个接口返回的 |
| 标签页 | 同时监视多个标签页时出现，只看某一个标签页的请求 |
| 类型 | 全部 / Fetch/XHR / 文档 / CSS / JS / 字体 / Img / 媒体 / 清单 / 套接字 / Wasm / 其他，按住 Ctrl 可多选 |
| 更多筛选 | 隐藏 data: 网址、隐藏扩展程序网址、仅显示失败请求、仅显示第三方请求 |
| 域名分类 | 左侧按域名列出请求数量，区分「监视的网站」和「第三方」，点击即可只看某个域名 |
| 详情 | 标头、载荷（查询参数 / 表单 / JSON）、预览（JSON 树、图片）、响应（格式化、复制、另存为）、消息（WebSocket / SSE）、发起程序（调用堆栈）、时间 |
| 右键菜单 | 复制网址、复制为 cURL（cmd / bash）、复制为 fetch、复制响应内容、复制请求/响应标头、只看/隐藏此域名、只看此标签页 |

跨站 iframe 和 Web Worker 里发出的请求也会被抓到。

## 为什么能绕过网站的反调试

插件通过 `chrome.debugger` 接口，只启用 Network 模块来拿数据，不打开 DevTools 窗口，也不启用 Debugger 和 Runtime 模块。因此：

- 页面里的无限 `debugger;` 断点不会让页面暂停（已用测试页对照验证：启用 Debugger 模块时页面会卡住，插件连接时页面正常运行）
- 靠窗口尺寸变化检测 DevTools 的手段不会触发，因为面板在独立窗口里

浏览器顶部的调试提示条会让页面可视高度变小约 40 像素。一般不会触发检测，个别网站如果对此敏感，可以先连接、再刷新页面。

## 限制

- 不能监视 `edge://` 内部页面、扩展商店页面和其他插件的页面
- 如果公司或学校用组策略禁用了开发者工具，「开发人员模式」和调试接口通常也会被禁用。这时插件会在窗口里直接提示无法连接
- 同一个标签页同时只能被一个调试类插件连接
- 数据只保存在窗口内存里，关掉窗口就没了，需要保留的话请先「导出 HAR」。最多保留 20000 条请求
- 图片、字体、媒体的响应内容在查看时才去获取。如果页面请求非常多，浏览器可能已经释放了较早的响应内容，这时会提示「响应内容已不可用」
- 「·补录」的请求没有响应内容（见上文「多个标签页 / 新窗口」）

## 文件结构

```
manifest.json      插件清单（Manifest V3）
background.js      点击图标时打开面板窗口；已在监视的标签页则切换到现有面板
viewer.html/.css   网络面板界面
src/capture.js     连接单个标签页、启用 Network 模块、自动附加 iframe / Worker
src/session.js     监视会话：管理多个标签页，自动跟随新窗口 / 同网站标签页
src/prelog.js      用 webRequest 补录调试器漏掉的请求（连接前、页面切换瞬间）
src/store.js       把网络事件合并为请求记录，获取响应体
src/filter.js      类型分类与筛选语法
src/detail.js      详情面板
src/jsonview.js    JSON 树
src/export.js      HAR 导出、cURL / fetch 生成
src/viewer.js      面板主逻辑（列表、筛选、标签页管理、右键菜单等）
icons/             图标
```

调试面板本身：在面板窗口里按 F12，控制台中可用 `__netMonitor.netStore.entries` 查看全部原始记录，`__netMonitor.session.list()` 查看监视中的标签页。
